# 問題分析方法論 Problem Analysis Methodology — 總覽

> 本檔是公開快照：只列出隨 `harness-skills` plugin 附帶的條目（01–15、23，以及 24／25 的程序與調用規格）。

**所屬 MOC：** [[MOC_問題分析方法論]]

這是一個 meta-level 的知識地圖：**不是研究某個生物 / 物理現象，而是研究「怎麼問對問題」本身**。所有筆記彙整自管理顧問業、學術研究方法論、批判性思考、決策科學等領域，目的是：

1. 在面對新研究題目 / 新專案 / 新決策時，有一套**系統化提問流程**，讓問題框架不會有盲點
2. 給 learning-notes skill 一個可參考的方法論基底 — 未來產出任何學習筆記、研究計畫、實驗設計時，都先走過一遍這層方法論
3. 給 advisor-dialogue skill 一個提問題庫 — 一問一答對話時，從方法分支抽問題

## 🗺️ 方法論地圖（按使用情境分類）

### A. 形成研究問題 (Research Question Formation)

當你還在「我想研究 X，但不確定問題是什麼」階段：

- [[01_Heilmeier_Catechism|01 Heilmeier Catechism — DARPA 8 問]]：研究提案經典骨架
- [[02_FINER_PICO|02 FINER + PICO — 醫學研究問題篩選]]：可行性 / 興趣 / 新穎 / 倫理 / 相關性
- [[12_Popper_Falsifiability|12 Popper Falsifiability — 可證偽性]]：假說必須能被推翻才是科學

### B. 拆解大問題 (Problem Decomposition)

當問題太大、太抽象，需要切成可操作的子問題：

- [[03_MECE_Issue_Tree|03 MECE + Issue Tree — McKinsey 拆解法]]：互斥且窮盡的子問題樹
- [[04_SCQA_Pyramid_Principle|04 SCQA + Pyramid Principle — Minto 結構化溝通]]：找出真正的核心問題
- [[05_5_Whys_Fishbone|05 5 Whys + Fishbone — 根因分析]]：追問因果鏈到底

### C. 檢驗論證強度 (Argument Validation)

當你已經有一個假說 / 方法 / 結論，要檢查它站不站得住：

- [[07_Socratic_Method|07 Socratic Method — 蘇格拉底式追問]]：透過追問逼出對方自己的不一致
- [[08_Toulmin_Argumentation|08 Toulmin Argumentation — 論證六元素]]：claim / grounds / warrant / qualifier / rebuttal / backing
- [[09_Steelman_Red_Team|09 Steelman + Red Team — 逆向自我攻擊]]：先把對手立場講到最強再反駁

### D. 預判失敗 (Failure Prediction)

當計畫已經要動手，要在啟動前找出致命弱點：

- [[06_Pre_mortem|06 Pre-mortem — Klein 假設失敗回推法]]：假設 1 年後已經失敗，逆推失敗原因

### E. 實驗 / 因果推論 (Experimental Design & Causal Inference)

當要從「現象觀察」過渡到「實驗驗證」：

- [[14_DOE_Confounding|14 DOE + Confounding — 實驗設計與混淆變因]]：控制 / 隨機化 / 重複 / 區組
- [[13_Bradford_Hill|13 Bradford Hill criteria — 因果性 9 條]]：流行病學因果推論強度
- [[15_Observable_Method_Fit|15 Observable-Method Fit — 量測層方法論]]：observable → mechanism → method 對齊（兩份實驗室教學提問清單的方法論版本）

### F. 反推使用者需求 (Customer-Driven Design)

當你在做工程系統 / 產品 / 工具：

- [[11_Working_Backwards|11 Working Backwards (Amazon PR/FAQ) — 從終點反推]]：先寫使用者看到的東西，再回推實作

### G. 確保認知層次 (Cognitive Depth)

當你想確保自己的問題不是停留在「記憶/理解」層而是真的進到「分析/評估/創造」層：

- [[10_Bloom_Taxonomy|10 Bloom Taxonomy — 認知層次六級]]：remember → understand → apply → analyze → evaluate → create

### I. 制度與宏觀結構分析 (Institutional & Macro-Structural Analysis)

當你要解釋「為什麼同樣的努力／技術／資源，在不同環境回報差一個數量級」時：

- [[23_Weber_Institutional_Economic_Analysis|23 Weber Institutional Economic Analysis — 韋伯制度經濟分析法]]：以「可計算性」為主變數拆解制度環境；含政治租金 vs 市場報酬、家計/經營分離、傳統主義摩擦力清單，以及「常數不能解釋變數」因果紀律。金融/產業/國家風險分析用
- [[24_Weber_Historical_Institutional_Analysis/02_韋伯式經濟史分析方法|24 Weber Historical Institutional Analysis — 韋伯式歷史制度分析法]]：用制度維度、行動者、跨案例對照、因果角色、條件合取、反事實與來源審計，解釋制度的形成、分岔、持續與崩解。跨 skill 規格見 [[24_Weber_Historical_Institutional_Analysis/10_跨Skill調用規格|調用契約]]

### J. 行為、決策與理論壓力測試 (Behavior, Decision & Theory Stress Testing)

當你要判斷一個理性 benchmark、行為機制或市場主張是否經得起反例、重現與場域檢驗時：

- [[25_Thaler_Behavioral_Anomaly_Analysis/02_異常驅動的理論壓力測試方法|25 Anomaly-Driven Theory Stress Test — 異常驅動的理論壓力測試]]：以 `Benchmark → Break → Replicate → Generalize → Discriminate → Revise` 檢驗理論；分開異常存在、機制識別、外部效度與福利推論。機制鑑別見 [[25_Thaler_Behavioral_Anomaly_Analysis/07_行為機制鑑別矩陣|行為機制鑑別矩陣]]，跨 skill 規格見 [[25_Thaler_Behavioral_Anomaly_Analysis/10_跨Skill調用規格|調用契約]]

## 🎯 給 learning-notes skill 的標準工作流

未來 learning-notes skill 被觸發時，**在產出筆記前先走過下列檢查清單**：

```
1. 這個學習主題屬於哪一類？
   - 純概念解釋 → 重點是 [[10_Bloom_Taxonomy]] 確保打到 analyze/evaluate 層
   - 一篇論文 → [[08_Toulmin_Argumentation]] 拆解論證 + [[09_Steelman_Red_Team]] 找弱點
   - 一個方法 / 技術 → [[01_Heilmeier_Catechism]] Q1-Q4 + [[15_Observable_Method_Fit]]
   - 一個研究問題 → [[02_FINER_PICO]] + [[12_Popper_Falsifiability]]
   - 制度 / 產業演化 / 國家—市場 / 組織史 → [[24_Weber_Historical_Institutional_Analysis/10_跨Skill調用規格]] + [[09_Steelman_Red_Team]]
   - 行為異常 / 決策理論 / replication / 市場錯價 → [[25_Thaler_Behavioral_Anomaly_Analysis/10_跨Skill調用規格]] + [[15_Observable_Method_Fit]]

2. 在「目前已知 / 真正未知」section，套用：
   - [[01_Heilmeier_Catechism]] Q2 (state of art)
   - [[03_MECE_Issue_Tree]] 拆已知 vs 未知

3. 在「方法 / 實驗」section，套用：
   - [[15_Observable_Method_Fit]] 全部 6 問
   - [[14_DOE_Confounding]] 控制與混淆檢查

4. 在「限制 / Discussion」section，套用：
   - [[09_Steelman_Red_Team]] hostile reviewer 視角
   - [[08_Toulmin_Argumentation]] qualifier + rebuttal
   - [[06_Pre_mortem]] 失敗模式預判

5. 在「結論 / 下一步」section，套用：
   - [[11_Working_Backwards]] 從理想終點反推
   - [[10_Bloom_Taxonomy]] 確保有 create 層的延伸題
```
